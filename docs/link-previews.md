# Best-effort messenger previews

Research and implementation checked on 2026-10-16. Client limits can change, and a messenger chooses its own card layout. This app supplies standards-based hints; it cannot force an unfurl, bypass a user's preview settings, or invalidate a messenger's cached card.

The [Open Graph specification](https://ogp.me/) defines the shared metadata contract. A single image avoids first-tag/last-tag differences between parsers. No fake platform identity, article date, or ActivityPub endpoint is added: this is a video-sharing site, not an impersonation of its original source.

## Thumbnail selection and failures

1. Try the thumbnail URL supplied by yt-dlp. Fetch it through the same public-address-only proxy as downloads, including redirects. Accept only JPEG/PNG/WebP, bound the response to 5 MiB, and time out after six seconds.
2. If unavailable or invalid, sample the downloaded video near its beginning (10% in, capped at three seconds), then try its first frame or existing poster.
3. Fit the full image inside a 1200 × 630 JPEG without cropping portrait media. Retry JPEG compression to keep the result below 512 KiB. Cache it locally; preview fetchers never need access to the original platform.
4. If generation fails or reaches its 25-second budget, keep the valid downloaded video. Serve the existing poster if usable, otherwise a 180 × 180 PNG app icon and a compact summary card.

The watch player's poster is separate from the messenger thumbnail, so portrait playback keeps its original proportions. Preview and optional dimension failures do not turn a successful media download into a failed job. Existing ready shares without dedicated previews are upgraded in the background at startup using their local files.

Generated images use `/preview/{id}/{content-hash}.jpg`. A changed image gets a changed URL; this avoids reusing an image cache key. It cannot force a messenger to refetch a previously cached page. Share after the job reaches `ready` for the best result.

## Deployment and validation

Serve the page, image, and video without authentication or cookie challenges. Use a reachable HTTPS hostname and set `PUBLIC_URL` to that origin behind a reverse proxy. The local `http://...:7543` interface remains usable but does not qualify for Signal previews. Do not trust arbitrary forwarded headers to manufacture preview URLs.

The tests parse HTML without JavaScript, exercise several crawler user agents, validate image dimensions/type/size and HEAD responses, block private thumbnail fetches, and simulate thumbnail-generator failure while checking that the MP4 remains available. These are compatibility checks, not a live Signal/WhatsApp/Telegram/Discord/iMessage delivery test. No messages are sent automatically.
